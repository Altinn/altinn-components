# Skyra surveys

`SkyraSurvey` loads the Skyra survey SDK once the user has consented, and not before. It renders nothing.

Skyra serves its script unversioned and updates it continuously, so it cannot be pinned with Subresource
Integrity. The component instead points at a dated copy we host ourselves and passes the matching hash, so the
browser refuses to execute the script if the bytes differ from the ones that were reviewed.

## Usage

Render it once, near the root of the app, somewhere that stays mounted across navigation so a changed answer is
picked up on every page.

```tsx
import { SkyraSurvey, useConsent } from "@altinn/altinn-components";

const { consent } = useConsent();

<SkyraSurvey consent={consent.statistics} />;
```

`consent` is the only required prop. Wire it to the statistics category of your cookie banner and let it
follow changes, the component handles both a fresh click and a returning user who consented earlier.
`useConsent` is the ready-made source for it, but any boolean works if your application already tracks
consent itself.

Do not load Skyra any other way. A `<script>` tag or `window.SKYRA_CONFIG` in the page or in a tag manager loads
the SDK regardless of consent, and leaves the component nothing to gate.


Nothing is requested before consent, not even the script.

## Route changes (for SPA only)

Survey targeting is evaluated per URL, so single-page apps must tell Skyra when the route changed. The hook
takes whatever value changes on navigation, so it works with any router. Before consent, and after a
withdrawal, it does nothing.

```tsx
import { useSkyraReload } from "@altinn/altinn-components";

useSkyraReload(useLocation().pathname); // React Router
useSkyraReload(usePathname()); // Next App Router
useSkyraReload(router.asPath); // Next Pages Router
```

## Debugging

```tsx
<SkyraSurvey consent={hasConsent} debug />
```

Enables Skyra's own debug logging and prints its diagnostic dump once. Logging from the SDK's own
initialisation is not captured. Note: the flag can only be set after the script has loaded, so nothing is logged
before consent.

## Why nothing shows up

By far the most common cause is targeting. Skyra matches the hostname of a show rule by **exact equality**,
with a leading `www.` as the only alias. `localhost` does not match `app.localhost`, and `altinn.no` does not
match any subdomain of it. Every hostname you want surveys on needs its own show rule in Skyra, including the
one you develop against.

After that, check in order: that a survey is published and live, that `consent` is actually `true`, since
without it there is no script at all, and that the survey's own retake and retrigger timers have not already
been satisfied for this visitor.

## Cookies to register in your cookie banner

All three are first-party and functional.

- **`skyra.state`** — visitor id and the status of each survey, so a survey that has been answered or
  dismissed is not shown again. Lasts 365 days.
- **`skyra.<survey-slug>`** — answers in progress while a survey is being filled out, so it can be started on
  one page and finished on another. Session, and cleared when the survey is completed or closed.
- **`skyra._test`** — verifies that cookies work at all. Momentary, deleted immediately after the check.
